One command to restart the server onto a new version of imux without losing your layout: `imux restart-server`. Upgrade if you want installed fixes to apply to the server you already have running, or if a new imux refuses to attach to an older server.

## Added

- **`imux restart-server`.** A running server keeps the old code until it exits, so after you install a new imux the fixes do not apply to it yet, and a new client may refuse to attach when the protocol changed. This command stops the server in the way that saves its sessions, starts this imux, and attaches, so you land back in your sessions. The layout, the directories, the programs in `restore-commands`, and Claude Code sessions with their names and conversations come back; other programs end and the scrollback is lost.
  - It asks first (`Restart it? [y/N]`), telling you what the server holds (sessions, windows, and the clients that will be disconnected) and what is lost. `--yes` skips the question for scripts, and without a terminal and without `--yes` it refuses. `--detach` stops after the server has ended instead of attaching.
  - It warns when `autosave-interval` is 0, because then nothing is saved, and when `restore-on-start` is off, because then only `imux restore` brings the sessions back. After the server ended it checks that a new autosave was written, and says so if not.
  - It works against a server of any version, also an older one whose protocol this imux does not speak, because it stops the server with a signal and not with a message.
  - Run it from a terminal outside imux. A pane ends with the server, so inside a pane the command refuses.

## Changed

- The message you get when a new imux meets an older server now names the new command.
- Under the hood: the build checks for a class of logic mistakes (such as a condition that can never matter) that newer Rust versions stopped checking by default.

No keys, options, or defaults changed, and saved sessions load as before.

## Install or upgrade

```sh
brew upgrade kingepic84/tap/imux
```

or

```sh
curl -fsSL https://imux.cc/install.sh | bash
```

then run `imux setup` again if you have not since 0.2.1. To put the new version to work on your running server, run `imux restart-server` from a terminal outside imux. If your server is older than 0.3.0 it does not have the command itself, but the new binary does: the command only needs the server to accept a signal.

## Which file to download

Most people should use Homebrew or the install script, which pick the right file. By hand: each archive holds the `imux` binary alone, and the `.sha256` next to it is its checksum.

| System | File |
| --- | --- |
| macOS, Apple silicon (M1 and later) | `imux-aarch64-apple-darwin.tar.gz` |
| macOS, Intel | `imux-x86_64-apple-darwin.tar.gz` |
| Linux, 64-bit ARM | `imux-aarch64-unknown-linux-gnu.tar.gz` |
| Linux, 64-bit x86 | `imux-x86_64-unknown-linux-gnu.tar.gz` |
